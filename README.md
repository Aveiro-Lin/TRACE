# TRACE

## TRACE for Integrated ECG Interpretation from Waveforms to Diagnosis and Text Generation

<p align="center">
  <img src="assets/main_architecture.png" alt="TRACE architecture" width="100%">
</p>

TRACE (**T**ransferable **R**epresentation with **A**daptive **C**ontrol and local **E**nhancement) is a stage-wise framework that connects ECG waveform representation, multi-label diagnosis, and diagnosis-conditioned text generation. It is initialized from [CoRe-ECG](https://arxiv.org/abs/2604.11359) and exposes continuous global/local features alongside discrete ECG tokens.

The current implementation follows the manuscript's three-stage organization:

1. **Stage I — TRACE ECG Foundation Interface.** A frozen CoRe-ECG encoder feeds a trainable latent-query interface that produces global latent features, patch-aligned local features, and three serialized ECG tokens. The interface is trained with waveform reconstruction and short-horizon prediction.
2. **Stage II — Morphology-Aware Diagnostic Refinement.** A diagnostic encoder copy is initialized from Stage I. The Global Base Pathway is fitted first; it is then frozen while the Patch Residual Pathway learns a scaled local correction in logit space.
3. **Stage III — Diagnosis-Informed Report Control.** A separately initialized control encoder predicts form/rhythm controls. These controls are rendered with the refined Stage-II diagnoses and the three retained Stage-I ECG tokens before LoRA-adapted Phi-3 decoding.

TRACE is trained stage by stage rather than as one end-to-end model. The diagnostic and control encoders start from separate copies of the Stage-I checkpoint and are subsequently adapted independently; they are not a permanently weight-shared encoder.

This repository contains the public workflows used for PTB-XL, CPSC2018, Ningbo, and Anzhen-ECG. PTB-XL is used for both diagnosis and statement-derived report generation. CPSC2018 and Ningbo are used for diagnosis and label-efficiency evaluation; their auxiliary structured-control scripts are not presented as matched narrative-report benchmarks. The private institution-internal cohort described in the manuscript is not distributed here.

## Results reported in the current manuscript

Public diagnosis results are macro-averaged percentages:

| Dataset | CoRe-ECG F1 / AUROC | TRACE F1 / AUROC |
|---|---:|---:|
| PTB-XL | 69.5 / 94.2 | **71.2 / 94.8** |
| CPSC2018 | 84.0 / 97.9 | **84.0 / 98.5** |
| Ningbo | 43.4 / 92.2 | **52.0 / 96.0** |

On 2,198 PTB-XL fold-10 statement-derived reports, TRACE obtains BLEU-4 67.48, ROUGE-L 82.29, BERTScore-F1 90.42, CIDEr-D 6.52, and parsed report-diagnostic F1 34.95. These values describe the fixed manuscript evaluation and should not be interpreted as unrestricted clinical report-generation performance.

For Anzhen form/rhythm report-control adaptation, the locked real-patient test results are:

| Adaptation data | Macro-AUROC | Macro-AUPRC | Macro-F1 |
|---|---:|---:|---:|
| 541 real training records | 0.7699 | 0.3475 | 0.3454 |
| 541 real + 396 reviewed derived variants | **0.8008** | **0.3796** | **0.4063** |

The 396 variants are label-preserving, training-only augmentations derived from real training parents. They are not independent patients or clinical acquisitions, and all validation and test records are genuine real-patient records.

## Installation

Create the Python environment following `env/README.md`. The tested setup uses Python 3.10, PyTorch 2.5.1, CUDA 11.8, and the Hugging Face/PEFT training stack.

```bash
conda create -n trace python=3.10 -y
conda activate trace
python -m pip install --upgrade pip
```

Then install the pinned dependencies:

```bash
python -m pip install -r requirements.txt
```

See `env/README.md` for CUDA-specific PyTorch guidance and the optional Anzhen
PDF-package construction dependency.

## Data and Checkpoints

Public ECG waveform files are not redistributed. Prepare the datasets from their original providers and place metadata or preprocessed arrays under `data/`, or pass explicit paths to the scripts.

This release does not redistribute trained dataset-specific weights. Only the shared CoRe-ECG MIMIC-IV-ECG-pretrained encoder initialization is kept:

```text
ckpt/
  pretrained_weight/CoRe-ECG_mimic_encoder.pth
  ptbxl/       # empty output skeleton; generated by PTB-XL training
  cpsc2018/    # empty output skeleton; generated by CPSC2018 training
  ningbo/      # empty output skeleton; generated by Ningbo training
  anzhen/      # optional local output skeleton for adapted checkpoints
```

Run the training commands below to regenerate ECG tokenizers, diagnosis checkpoints, report-control heads, LoRA adapters, and merged report models.

The bundled initialization is associated with the
[CoRe-ECG paper](https://arxiv.org/abs/2604.11359) and has SHA-256
`24472f7ab730a49054ebcf6bce43c163da37f376bcfb0e6fadbf28c4fd86c110`.
See [`ckpt/README.md`](ckpt/README.md) for provenance and redistribution details.

Stage III-B uses Phi-3-mini-4k-instruct. Point the report scripts to a local model snapshot containing the model configuration, tokenizer, and safetensor shards:

```bash
export TRACE_BASE_LM_PATH=/path/to/Phi-3-mini-4k-instruct
```

## Usage

The commands below are plain foreground commands. Set `CUDA_VISIBLE_DEVICES` yourself when selecting GPUs.

### PTB-XL

Prepare:

- `data/ptbxl_database.csv`
- `data/scp_statements.csv`
- `data/records2250.npy` for diagnosis/tokenizer training
- `data/full_data.npy` for report-control/report training

Train the ECG tokenizer:

```bash
python train_tokenizer_ptbxl.py
```

Train the report-control head:

```bash
python report_control_train_ptbxl.py \
  --metadata-csv data/ptbxl_database.csv \
  --scp-statements-csv data/scp_statements.csv \
  --signals-npy data/full_data.npy
```

Train the diagnosis refinement checkpoint:

```bash
python train_diagnosis_ckpt.py \
  --dataset ptbxl \
  --metadata-csv data/ptbxl_database.csv \
  --scp-statements-csv data/scp_statements.csv \
  --signals-npy data/records2250.npy
```

Evaluate diagnosis:

```bash
python eval_diagnosis_ptbxl.py \
  --eval-only \
  --downstream-checkpoint ckpt/ptbxl/downstream_refined/best.pt \
  --metadata-csv data/ptbxl_database.csv \
  --scp-statements-csv data/scp_statements.csv \
  --signals-npy data/records2250.npy
```

Train the report language branch:

```bash
python train_report_ptbxl.py
```

Generate PTB-XL reports:

```bash
python infer_report_ptbxl.py \
  --split test \
  --output_prefix data/generated_ptbxl_st2
```

Evaluate PTB-XL report-generation metrics:

```bash
python eval_ptb_report_generation_metrics.py \
  --input-json data/generated_ptbxl_st2_reports.json \
  --output-json data/generated_ptbxl_st2_nlg_metrics.json \
  --bertscore
```

### Anzhen-ECG resource and site adaptation

The Anzhen-ECG package is distributed separately from this code repository. It provides de-identified, PTB-XL-compatible metadata plus WFDB and TRACE-compatible waveform representations. The real resource contains 1,385 resting ECG records from 1,377 patients. The paper's Stage-III-A report-control experiment uses a patient-disjoint 50:50 development/test protocol: the development half is divided 80:20 for training and validation, giving 541 real training records from 538 patients, 134 real validation records from 134 patients, and 677 locked real test records from 673 patients among the 1,352 control-eligible records. The remaining 33 records from 32 patients have no mapped control target and are excluded from that experiment.

The underlying real cases and source clinical diagnoses underwent clinician verification; the downstream PTB-XL/SCP-compatible labels are deterministic mappings and were not separately clinician-adjudicated. The signals are vector-reconstructed lead traces rather than native digital exports. The WFDB representation retains unobserved intervals as missing values and supplies validity masks. The finite TRACE array independently resamples and periodically completes observed lead segments to `(12, 2500)` at 250 Hz for loader compatibility; this operation does not infer missing physiology or restore cross-lead synchrony.

The derived augmentation package contains 396 clinician-reviewed, label-preserving variants generated only from real training parents. They are training-only augmentations: they are not new patients, new clinical acquisitions, independent clinical observations, validation samples, or test samples. All validation and locked-test records remain genuine real-patient records. See [`anzhen/README.md`](anzhen/README.md) for the schema, provenance boundaries, and data-preparation utilities.

Required PTB-XL initialization checkpoints:

```text
ckpt/ptbxl/
  tokenizer/ecg_tokenizer_level_2_code_256_len_2250_ratio_0.1_st2.pth
  downstream_base/best.pt
  downstream_refined/best.pt
  report_control/best.pt
```

By default, the launchers look for the real and derived packages at `data/anzhen_external/` and `data/anzhen_derived/`, respectively, and use `python3` from the active environment. Override these portable defaults when the assets are stored elsewhere:

```bash
export ANZHEN_DATA_ROOT=/path/to/Anzhen-ECG
export ANZHEN_DERIVED_ROOT=/path/to/Anzhen-ECG-derived
export TRACE_PYTHON=python
export TRACE_GPU=0
```

The current manuscript reports report-control adaptation rather than Anzhen free-text generation. The following locked zero-shot diagnosis evaluator is retained as an optional reproducibility utility and is not part of the reported adapted Anzhen result:

```bash
scripts/run_anzhen_external_ptbxl.sh
```

The following additional utility adapts the PTB-XL TRACE diagnosis model under the patient-level 40:10:50 protocol:

```bash
scripts/run_anzhen_finetune_diagnosis_50_50.sh
```

An alternative 70:15:15 diagnosis sensitivity configuration is also retained but is not the manuscript's primary Anzhen protocol:

```bash
scripts/run_anzhen_finetune_diagnosis_70_15_15.sh
```

Adapt the Stage-III-A report-control branch with real training records only:

```bash
scripts/run_anzhen_report_control_50_50.sh
```

Run the manuscript configuration with the same locked real split plus the 396 clinician-reviewed, label-preserving derived variants in training only:

```bash
scripts/run_anzhen_report_control_derived_50_50.sh
```

For an unattended long run, wrap any launcher with `nohup`, for example:

```bash
mkdir -p logs
nohup env TRACE_GPU=0 scripts/run_anzhen_report_control_derived_50_50.sh \
  > logs/anzhen_report_control_derived.log 2>&1 &
echo $! > logs/anzhen_report_control_derived.pid
```

For report-control experiments, the frozen `trace_compat/paper_report_control_split_seed42.csv` shipped with the separate data package is authoritative. The launcher does not re-search or silently replace that split. The launchers accept additional CLI arguments after their defaults, so smoke tests and alternative output directories do not require editing the scripts.

### Label-efficiency experiments

The manuscript's public label-efficiency analysis uses training ratios `0.05`, `0.10`, `0.25`, `0.50`, and `1.00` with seeds 42, 43, and 44. For every dataset/ratio/seed combination, train the CoRe-ECG base run before TRACE so that both methods share the same selected training subset and TRACE can initialize from the matching base checkpoint:

```bash
python label_efficiency_train.py \
  --dataset ptbxl \
  --method core \
  --ratio 0.25 \
  --seed 42

python label_efficiency_train.py \
  --dataset ptbxl \
  --method trace \
  --ratio 0.25 \
  --seed 42
```

Replace `ptbxl` with `cpsc2018` or `ningbo` and supply the corresponding data arguments when they differ from the repository defaults. Validation and test partitions remain fixed; only the training partition is subsampled.

## Notes

- PTB-XL supports narrative report-generation evaluation with BLEU, METEOR, ROUGE-L, BERTScore, and CIDEr-D.
- CPSC2018 and Ningbo do not provide the same public paired narrative report targets, so their report scripts are used for structured control/report consistency rather than PTB-XL-style narrative report benchmarking.
- Anzhen adaptation is patient-disjoint. Derived variants inherit their real training parent's identity and labels and are never counted as independent patients or placed in validation/test sets.
- See `data/README.md` for the files retained in this repository and the public data files that must be downloaded separately.
